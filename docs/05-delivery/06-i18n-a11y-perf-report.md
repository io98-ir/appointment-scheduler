# گزارش ترجمه، دسترس‌پذیری و کارایی (T6.3)

> وضعیت در پایان T6.3. هر عددی که اینجا آمده با اجرای واقعی همان دستور به‌دست آمده است. آنچه هنوز با ابزار خودکار نمی‌شود سنجید، در «باقیمانده» آمده است.

## ۱. ترجمه

**خط لوله (بدون WP-CLI):** `pnpm i18n` این کارها را می‌کند و `pnpm i18n:check` (در CI، job `i18n`) شکستن هر کدام را می‌گیرد.
- `tools/i18n/extract.php` رشته‌های PHP را با `nikic/php-parser` می‌خواند (`__`، `_e`، `_x`، `_n`، `_nx`، `esc_html__` و مانند آن؛ فقط literal).
- `tools/i18n/build.mjs` رشته‌های JS (پکیج‌های `admin`، `widget`، `shared` و `assets/blocks.js`) را با Babel می‌خواند و همه را در `languages/vaqtyar.pot` می‌ریزد.
- ترجمه فارسی دستی است: `languages/vaqtyar-fa_IR.po`. از آن `vaqtyar-fa_IR.mo` (PHP) و سه فایل JED برای اسکریپت‌ها ساخته می‌شود (`vaqtyar-fa_IR-vaqtyar-admin.json`، `…-widget.json`، `…-blocks.json`). نام فایل JED از handle می‌آید و `wp_set_script_translations()` آن را بی‌نیاز از hash پیدا می‌کند.

**نتیجه:** 527 رشته، 527 ترجمه شده (0 بدون ترجمه). `--check` این‌ها را هم می‌سنجد: هر رشته ترجمه غیرخالی دارد و placeholderهای printf (`%s`، `%1$d`، …) با مبدأ برابرند. نام ماه‌های شمسی با context «Jalali month» ترجمه شده‌اند، پس `DateFormatter` دیگر نام آوانگاری‌شده نشان نمی‌دهد (implementation-notes §2.6).

**بررسی en:** زبان مبدأ انگلیسی است و همان رشته‌های کد است. متن‌های ساخته‌شده از Domain کد خطا هستند، نه متن (principles §3)، و ترجمه‌شان در Presentation است.

**باقیمانده:** ترجمه را یک ویراستار فارسی‌زبان باید بخواند (اصطلاح‌ها: «نوبت» برای appointment، «پرسنل» برای staff، «شعبه» برای location، «خدمت» برای service). قالب‌های پیش‌فرض اعلان که در migration کاشته می‌شوند از قبل فارسی‌اند و در این فایل نیستند. یک ترجمهٔ en_US جدا لازم نیست.

## ۲. دسترس‌پذیری

**ممیزی خودکار (axe-core 4، در Vitest با jsdom):**
- `packages/admin/src/a11y.test.tsx`: هر 15 مسیر برنامه Admin (داشبورد، تقویم، نوبت‌ها، مشتریان، خدمت‌ها، دسته‌ها، پرسنل، منابع، شعبه‌ها، گزارش‌ها، تعطیلات، تنظیمات، وضعیت، ویزارد و صفحه 404) ← 0 تخلف.
- `packages/widget/src/widget.test.tsx`: ویجت در سه حالت (تقویم، فهرست ساعت‌ها، مرحله جزئیات) ← 0 تخلف.

**یافته و رفع:** axe روی تقویم ویجت `aria-required-children` گرفت: عنصر `role="grid"` بدون سطر و سلول. تقویم شبکهٔ CSS از دکمه‌هاست، پس نقش به `group` با برچسب ماه (`aria-label`) عوض شد. ماه جاری برای هر دو (عنوان و برچسب) یک متغیر است.

**محدودیت روش:** jsdom چیدمان ندارد، پس `color-contrast` خاموش است. صفحه‌ها با داده خالی یا نمونهٔ کوچک رندر شده‌اند.

**باقیمانده (دستی، پیش از انتشار):** کنتراست رنگ‌ها در تم روشن و تیره و با رنگ برند دلخواه (رنگ‌ها با متغیر `--vqy-accent` و کلیدواژه‌های رنگ سیستم‌اند، پس کنتراست دلخواه کاربر تضمین نمی‌شود)؛ پیمایش کامل با کیبورد در تقویم Admin (کشیدن نوبت با ماوس راه جایگزین «Move in calendar» دارد)؛ آزمون با NVDA یا VoiceOver روی ویجت.

## ۳. کارایی

| مورد | بودجه | اندازه‌گیری |
|---|---|---|
| ویجت (JS و CSS، gzip) | 40KB (ADR-007) | 15.5KB |
| برنامه Admin (gzip) | 150KB | 37.7KB |
| p95 پرس‌وجوی availability | زیر 40ms | زیر 40ms (T1.5، CI، `AvailabilityRestTest`) |
| درخواست بدون کار افزونه | بدون query اضافه | Migrator با schema به‌روز یک option autoload می‌خواند و query نمی‌زند (مستند در `Migrator` و `Plugin::boot()`؛ تست جدا ندارد) |

- گروه‌های Settings که هر درخواست می‌خوانند autoload هستند (`general`، `brand`، `modules`)؛ بقیه (ویزارد، قیمت‌گذاری، ورود مشتری، اعلان، ووکامرس، availability) نیستند.
- اسکریپت و استایل ویجت هنگام رندر shortcode یا بلوک enqueue می‌شوند، پس فقط صفحه‌ای که آن را دارد بارگذاری می‌کند (`Embeds::enqueue`).
- فایل‌های ترجمه: JSON ویجت 5.7KB و Admin 18KB خام و فقط در صفحهٔ خودشان inline می‌شوند؛ داخل بودجهٔ JS ویجت نیستند.

**باقیمانده:** اندازه‌گیری زمان واقعی صفحه (LCP و INP) روی سایت نمونه با Lighthouse، و پروفایل query روی داده حجیم (10 هزار نوبت) در T6.5.
